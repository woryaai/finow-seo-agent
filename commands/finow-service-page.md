# /finow-service-page

## Purpose

Create one conversion-oriented Finow money page with a single clear primary search intent and audience.

## Read first

- `AGENTS.md`
- `context/finow-brand.md`
- `context/finow-audiences.md`
- `context/finow-voice.md`
- `context/finow-compliance.md`
- `context/finow-product-facts.md`
- `references/iran-search.md`
- `references/on-page-seo.md`
- `references/content-quality.md`
- `references/internal-linking.md`
- `references/schema.md`
- `references/persian-writing.md`
- `keyword-map.md`
- `website-index.md`

## Step 1 - Select and protect intent

Use the provided topic or select the highest-priority unwritten service row.

Confirm:

- B2C or B2B
- target intent
- no existing URL already owns it
- product/service actually exists

If an existing page owns the intent, optimize/update that page instead of creating a duplicate.

## Step 2 - SERP and competitor read

Inspect priority organic results and relevant SERP features.

Capture:

- expected page type
- common objections/questions
- trust elements competitors use
- content gaps Finow can answer better

Do not copy competitor wording.

## Step 3 - Product fact gate

Every financial/payment claim must resolve to `context/finow-product-facts.md` or another verified current source.

A `REVERIFY` value cannot be turned into a live claim.

Unknown values become dependencies, not guessed copy.

## Step 4 - Page strategy

Define:

- one primary promise
- one primary CTA
- key user objection
- strongest verified proof
- parent hub and internal-link path

B2C CTA examples depend on real product flow: register, check eligibility, find service/merchant, book or continue payment.

B2B CTA examples: merchant signup, activation request, consultation or eligibility check.

## Step 5 - Draft page

Recommended visible hierarchy:

- H1 and clear promise
- audience/eligibility context
- how it works
- verified payment/credit information
- benefits
- trust/proof
- process
- FAQ
- related services/content
- primary CTA/form

Keep the hero focused. Do not bury the primary action under documentation-like copy.

## Step 6 - Conversion integrity

If a form is used, verify its destination.

If the form destination is unknown/broken, block `Ready`/publish status.

## Step 7 - SEO/GEO

Prepare:

- title/meta
- canonical
- heading hierarchy
- breadcrumbs
- relevant schema
- internal links
- direct answer passages for common questions
- reviewed date for volatile claims

## Step 8 - Quality gate and register

Score against `references/content-quality.md` and on-page checks.

Minimum content gate: 9/10.

Update `keyword-map.md` and `website-index.md`.

Do not publish directly.
