# Internal linking architecture

## Default graph

- blog/supporting article → relevant money page
- spoke → hub
- hub → important spokes
- vertical hub → related B2C service pages
- B2B educational content → merchant conversion page
- FAQs → deeper explanation when useful

## Rules

- no orphan indexable pages
- link for user relevance first
- avoid repetitive exact-match anchor stuffing
- do not create links to nonexistent future routes just to satisfy a graph
- important newly published pages should receive at least one contextual internal link

## Registry

Use `keyword-map.md` for planned relationships and `website-index.md` for actual page status.
